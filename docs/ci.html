SCREENCAST-MCP / CI

Record test runs in CI

Browser tests get a video of every failure for free. Desktop apps on Windows (Electron, WPF, WinUI, WinForms, games) don't. screencast-mcp record runs your test command while it records the runner's desktop, then turns a failure into a GIF and a contact sheet you can open from the run.

00:00THE COMMAND LINE

The same tools the MCP server exposes, without an MCP client. The command's exit code passes straight through.

npx -y @tmhs/screencast-mcp record --target full -- npm run test:e2e
  • --target: full (default), monitor:0, window:exe=MyApp.exe, or region:x,y,w,h.
  • --artifacts failure|always|never: when to make evidence.gif and contact-sheet.png (default failure).
  • --last 30: the GIF covers the last 30 s, where the failure usually is; 0 keeps it all.
  • --out, --fps, --no-gif, --no-contact-sheet, --discard-on-success.
  • --max-duration: whole seconds, 0 to 604800 (0 = no cap; default 3600).
  • --command-env NAME: run the command line stored in an environment variable, so quotes and & reach the shell unchanged.
  • --ocr-errors: on failure, OCR the end of the run and add the error lines it finds (secrets masked) to evidence.json.

Everything lands in screencast-evidence/ with an evidence.json summary. Any single tool works the same way: npx -y @tmhs/screencast-mcp call doctor, or call pipeline @recipe.json.

00:10THE ACTION

A composite action wraps it for windows-latest: it checks Node, installs ffmpeg if it is missing, records the command, uploads the evidence folder as an artifact, writes a job summary, and then fails the step with the command's exit code.

jobs:
  ui-tests:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@249970729cb0ef3589644e2896645e5dc5ba9c38 # v6.5.0
        with:
          node-version: 22
      - run: npm ci
      - uses: TMHSDigital/screencast-mcp@v0 # newest 0.x release; pin vX.Y.Z or a SHA to freeze it
        with:
          command: npm run test:e2e
          target: full          # or window:exe=MyApp.exe
          artifacts: failure    # GIF and contact sheet only when it fails

Outputs: exit-code, end-reason, gif, contact-sheet, recording, evidence-dir, artifact-name, and artifact-url. All inputs are in action.yml.

@v0 is a floating tag that each release moves to the newest 0.x version, so a broken main never reaches your CI; use a full version tag such as @v0.47.0 or a commit SHA to pin exactly. Pinning the action pins the CLI too: by default it runs the npm version the action was released with. Each job and matrix leg uploads its own artifact (screencast-evidence-<job>[-<index>]), so matrices do not collide. The Action is being published to GitHub Marketplace.

comment: true keeps one PR comment per job, created when the command fails and updated on later runs, with the exit code, how the recording ended, OCR'd errors, and a link to the evidence artifact. It needs permissions: pull-requests: write; fork PRs get a read-only token, so the step only warns. GitHub cannot show images stored in artifacts, so the GIF stays in the artifact.

00:20WHAT TO KNOW
  • Hosted Windows runners have an interactive desktop, so gdigrab records what your app draws. This repo records its own capture smoke test with the action on every change to it.
  • A recording holds whatever is on screen. Keep secrets off the runner's desktop, and remember artifacts are visible to anyone who can read the run.
  • For a longer suite, keep the default discard-on-success so green runs upload only evidence.json.
  • evidence.json records endReason. If the recording hit max-duration or crashed before the command finished, the run warns, because the GIF then shows the end of the recording rather than the end of the run.
